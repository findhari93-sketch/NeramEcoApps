# Nexus performance audit, 2026-09-22

## Scope and coverage
- **Focus:** none named ("run an audit"). The planner chose the foundation: the app config, all 7 layouts, and the 17 shared files with the highest fan-in. `route:api/auth/me` was added because every page boots from it.
- **Planner change first:** the planner ranked foundation units by fan-in alone. Layouts have no fan-in, so they sat behind about 240 shared files and never made a 25-unit budget. It now takes the config, then layouts from the root down, then shared files and packages by fan-in (guardrail test added).
- **Audited: 26 units.**
  - `config:nexus` (PROD-2 only; the rest was audited on 2026-09-21);
  - `layout:.`, `layout:(auth)`, `layout:(pad)`, `layout:(parent)`, `layout:(student)`, `layout:(teacher)`, `layout:(teacher)/teacher/students`;
  - 18 shared files: `lib/parent-token`, `impersonation-token`, `ms-verify` (remaining checks), `teams-sso`, `ttl-cache`, `staff-capabilities`, `api-errors`, `feature-flags`, `study-materials`, `photo-gate`, `timetable-window`, `parent-session`, `graph-app-token`, `pad/embedded`, `auth-cache`, `swr-cache`, and `hooks/useNexusAuth.tsx` (remaining checks);
  - `route:api/auth/me` (every route check except API-2).
- **Skipped as fresh:** none were on the path.
- **Re-audits:** 3 `stale:checks`: `config:nexus` (PROD-2), and the remaining checks on `ms-verify` and `useNexusAuth`. The other three units from 2026-09-21 (`NavBadgeProvider`, `api/notifications`, `api/nav-badges`) were not planned and stay `stale:checks`.
- **Coverage after this session:** 29 of 1,039 units audited. Still never audited: 1,010 (the 186 pages and nearly all 599 routes).
- **Evidence sources:**
  - `pg_stat_statements` and read-only queries on production (the /me queries, staff enrolments, heartbeat rows);
  - response headers and a GET of the manifest shortcut on production;
  - the local production build's chunk manifest (no new build was run);
  - the SWR 2.4.2 source in node_modules;
  - failing tests written before each fix;
  - code reading by five parallel reviewers, each finding re-checked against the code before filing.
- **Unavailable:** Vercel request logs (connector not authorised), authenticated Playwright (Entra MFA wall).

## Performance audit report
1. **Top problems:**
   - PERF-0025 (HIGH, redacted): client cache layer.
   - PERF-0023 (HIGH): refreshes after a write did nothing.
   - PERF-0024 (HIGH): a revoked parent was stuck in a redirect loop.
   - PERF-0026: a cold boot sent signed-in users to sign in on any /me failure.
   - PERF-0012: /me answered 401 for everything and cached "no classrooms" on a DB blip.
   - PERF-0033: the student heartbeat posts from hidden tabs (54% of rows are idle-only).
   - PERF-0053: the Firebase SDK ships to every route.
   - PERF-0029: nav items are buttons calling router.push, so nothing prefetches.
   - PERF-0013 and PERF-0014: Graph and database outages read as signed out.
   - PERF-0054: an expired session can redirect the page from a background poll.
2. **Production errors reported:** none this session. The PERF-0001 fix (#418/#423) was re-checked and holds. Three storage reads remain in `useState` initialisers; they are latent and masked by RoleGuard's spinner (PERF-0060).
3. **Failing or slow endpoints:**
   - `/api/auth/me` is fast in the database. Every query it runs averages under 0.2ms on production (users by `ms_oid` 0.06ms over 626k calls; enrolments with classrooms 0.13 to 0.17ms).
   - Its problems were error handling, not speed. See PERF-0012.
4. **Why refresh fixes it:**
   - A cold boot whose /me failed sent the user to sign in; a refresh started a fresh /me that usually succeeded.
   - The parent loop never cleared on refresh, because the stored session was never dropped.
5. **Slowest APIs:** not measured. Vercel logs were unavailable, and the DB side of `/api/auth/me` is under 1ms.
6. **Duplicate requests** (inferred from code):

   | Endpoint | Calls | Expected | Cause |
   |---|---|---|---|
   | `/api/nav-badges` | 1 to 2 per warm hard load | 1 | effect keyed on the `user` object (PERF-0037) |
   | `/api/auth/me` | 2 per library video open | 1 | `useWatchTracker` mounts a second auth hook (PERF-0056) |
   | `/api/devices/heartbeat` | 1 per minute from hidden tabs, plus a beacon per tab hide that always 400s | at most 1 per active minute | PERF-0033, PERF-0034 |
   | `/api/graph/photo?self=true` | 1 per parent load, always 401 | 0 | PERF-0048 |
   | `/api/students/stage-facts` | 0 on a warm hard load | 1 | `revalidateIfStale: false` (PERF-0031) |

7. **Largest components and bundles:**
   - The root layout loads 15 JS files: 1,405,648 B raw, 395,137 B gzip, measured from the last local build.
   - One chunk of that is the Firebase Auth SDK, which Nexus never uses: 98,195 B raw, 28,089 B gzip (PERF-0053).
   - The photo cropper and alumni screen are also in the root bundle (PERF-0042).
   - TopBar is 989 lines and useNexusAuth about 1,000; both are mostly markup or state and render rarely.
8. **Database and query bottlenecks:**
   - None in SQL for these units.
   - Cost is in round trips: the parent credential row is read 2 to 3 times per parent request (PERF-0020), and about 20 files read `nexus_settings` uncached (PERF-0021).
9. **Most expensive renders:**
   - The auth context value is rebuilt on each provider render, but it renders only about 5 times per boot. Not a finding.
   - The device-cache flush stringifies the whole cache twice on every write burst (PERF-0059, not measured).
10. **Recommended fixes:** per finding in `findings.jsonl`, field `fix`. All are Nexus-only except PERF-0015 and PERF-0053 (package option) and PERF-0032 (`packages/ui`), which rebuild all four apps.
11. **Estimated impact:** per finding, field `expected`. Measured baselines:
    - 952 of 1,773 heartbeat rows in 7 days record no activity (PERF-0033);
    - 28 KB gzip of Firebase on every route (PERF-0053);
    - 24 of 30 staff accounts have no live classroom, none of them active in 30 days (PERF-0038).
12. **Risk of each change:** per finding, field `risk`.
13. **Implementation order:**
    1. The fixes from this session, verified on staging.
    2. PERF-0013 and PERF-0014 (outages read as signed out).
    3. PERF-0033 to PERF-0036 (heartbeat and device registration).
    4. PERF-0053 (Firebase out of the bundle).
    5. PERF-0054 and PERF-0055 (session expiry and View as Student).
    6. PERF-0028 (error boundaries) and PERF-0029 (links and prefetch).
    7. The remaining MEDIUM findings, then LOW.

    - PERF-0028: `app/error.test.tsx`, `app/(parent)/error.test.tsx` and `app/global-error.test.tsx`.
