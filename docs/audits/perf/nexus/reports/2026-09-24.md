## Performance audit report
1. **Top problems**
   - PERF-0061: the reported-questions inbox fails on every load.
   - PERF-0062: failed reads are answered as 404 "not found", and expired tokens as 500.
   - PERF-0063: the drawer tabs hold skeletons over a failure, with no retry.
   - PERF-0064: drawer reads use the widest teacher token.
2. **Root cause of the reported production errors**
   - `GET /api/class-recaps/question-reports` 500: the query embed is ambiguous (two foreign keys to `users`) and names `users.full_name`, which does not exist. This is deterministic. It was proven on staging: the old select gets PGRST201 and the fixed one gets 200.
   - The other five failures (`/api/notifications` 500, `/api/timetable/notifications` 500 twice, `/api/timetable` 404, `/api/timetable/class-insights` 404) fit one database or proxy failure in the same minute. Each route reported it differently depending on how it caught errors.
     - `/api/notifications` classifies its errors, so its 500 is a real database failure.
     - The class-insights 404 named a class that exists in the classroom it gave (checked on prod), and no users share an `ms_oid`. So it was a failed read reported as "not found".
3. **The Attended tab stuck on skeletons.** `fetchWithToken` had no deadline, and the tabs never read SWR's `error`. SWR reports loading on every retry, so the tab showed skeletons, then an info note with nothing to press.
4. **Why refresh fixes it.** A reload re-runs the reads after the database recovers. Nothing was cached wrong.
5. **Slowest APIs:** not measured (no runtime logs available).
6. **Duplicate requests:** `/api/timetable/notifications?countOnly` appeared twice, which is the bell's mount plus one 60s poll, as designed. Nothing else was measured.
7. **Largest components and bundles:** not in scope this session.
8. **Database and query bottlenecks:** none measured. The one query failure is a schema mismatch (PERF-0061), not a slow query.
9. **Most expensive renders:** not in scope this session.
10. **Recommended fixes:**

    | Finding | Fix | App |
    |---|---|---|
    | PERF-0061 | FK-hinted embed, and read `name` | `@neram/database` (consumed by Nexus) |
    | PERF-0062 | `throwIfReadFailed` + `httpStatusForError` on four routes | Nexus |
    | PERF-0063 | 20s deadline in `fetchWithToken`, plus `InsightsLoadError` in the tabs | Nexus |
    | PERF-0064 | A read-only token prop for the panel's reads | Nexus |
11. **Estimated impact:**
    - The catch-up tab stops logging a 500 on every load, and reported questions reach teachers.
    - A database blip shows "Could not load the class" with Try again, instead of a false "not found" or endless skeletons.
    - Expired sessions answer 401, which the client can act on.
12. **Risk:** LOW for all four. Status codes change only on failure paths, and a real missing row still answers 404.
13. **Implementation order:** 0061, 0062, 0063 (all done); then 0064, once the other session's edits to the drawer files land.
14. **Needs approval before doing:** none. There are no index, RLS or cross-app changes. PERF-0061 touches `packages/database`, so deploying it rebuilds every app. Use the single-app deploy route if only Nexus should go.
15. **Fixed this session (all uncommitted):**
    - PERF-0061: `class-recap-reports.test.ts` (2 tests) and `question-reports/route.test.ts` (3 tests, new).
    - PERF-0062: `api-errors.test.ts` (3), `class-insights/route.test.ts` (+8), `timetable/notifications/route.test.ts` (5, new), `timetable/route.get-errors.test.ts` (4, new).
    - PERF-0063: `nexus-swr.test.ts` (+3), `InsightsLoadError.test.tsx` (4, new), `ClassAttendancePanel.load-error.test.tsx` (4, new).

## Findings

### PERF-0061 [HIGH] The reported-questions inbox fails on every load: its users embed is ambiguous and names a column that does not exist
- Units: route:api/class-recaps/question-reports
- Check: DB-1 | Evidence type: measured
- Location: packages/database/src/queries/nexus/class-recap-reports.ts:178
- Root cause: `student:users(full_name, avatar_url)` has two faults:
  - `nexus_class_recap_question_reports` has two foreign keys to `users` (`student_id`, `resolved_by`), so PostgREST refuses the join with PGRST201.
  - `users` has no `full_name` column; it is `name`.
- Evidence: the prod catalog shows both FKs and no `users.full_name`. On staging PostgREST the old select returns HTTP 300 PGRST201 and the fixed select returns 200. The prod console shows a 500 on each catch-up load.
- User impact: teachers would never see a student's "report a mistake". `RecapReviewQueue` shows the failure as an empty list. Prod has 0 reports so far, so none were lost.
- Technical impact: one 500 per teacher load of Catch-up.
- Recommended fix: `users!nexus_class_recap_question_reports_student_id_fkey(name, avatar_url)`, and map `student_name` from `name`. The route also checks its classrooms read and uses `httpStatusForError`.
- Risk: LOW.
- Expected improvement: the route answers 200 and lists open reports.
- Status: fixed (uncommitted)

### PERF-0062 [HIGH] Timetable, class-insights and timetable-notifications report a failed read as 404 'not found' and an expired token as 500
- Units: route:api/timetable, route:api/timetable/class-insights, route:api/timetable/notifications
- Check: ERR-4 | Evidence type: inferred
- Location: class-insights/route.ts:104-126, timetable/route.ts:69-94, timetable/notifications/route.ts:24-28
- Root cause:
  - The `.single()` reads kept `data` and dropped `error`.
  - class-insights also dropped the errors from its attendance, RSVP, absences and away-window reads. A failed attendance read therefore looked like a class Teams had not synced.
  - The catch blocks answered 500 for everything, including a missing Authorization header.
- Evidence: a 404 for class 1f97a143 in classroom 8876a8fc, which exists in that classroom (checked on prod). No duplicate `ms_oid`. Four sibling failures happened in the same minute.
- User impact: a database blip reads as "this class does not exist" and an empty week. A lapsed session reads as a server error.
- Technical impact: clients cannot tell retry from re-auth from real absence.
- Recommended fix: `throwIfReadFailed(error, what)` in `lib/api-errors.ts`. PGRST116 passes; any other error throws `ApiError` 503. Catches use `httpStatusForError` and `messageOf`. The timetable route treats a malformed classroom id (22P02) as missing.
- Risk: LOW.
- Expected improvement: a failed read answers 503, a missing row 404, an expired token 401.
- Status: fixed (uncommitted)

### PERF-0063 [MEDIUM] Class drawer Attended and Missed tabs hold skeletons over a failed or hung load, with no error and no retry
- Units: shared:src/lib/nexus-swr.ts
- Check: LOAD-1 | Evidence type: inferred
- Location: lib/nexus-swr.ts:49; AttendedTab.tsx:267; MissedTab.tsx:596; ClassAttendancePanel.tsx:145
- Root cause: there was no deadline on `getToken()` or `fetch`, and the panel never read SWR's `error`.
- Evidence: the prod screenshot shows three skeletons on the Attended tab while class-insights had answered 404.
- User impact: a failed load looks like a slow one, and the only way out is closing the drawer.
- Technical impact: a hung MSAL call pins `isLoading` true for good.
- Recommended fix:
  - A 20s deadline covering the token and the request (`NexusFetchError` 408).
  - The panel passes `insightsError`, `insightsRetrying` and `onRetryInsights`.
  - Both tabs render `InsightsLoadError` before the loading branch: an error Alert (`role="alert"`) with the route's message and a 48px Try again, which is disabled while retrying.
- Risk: LOW.
- Expected improvement: an error with Try again appears at once. A hang becomes that error within 20s.
- Status: fixed (uncommitted)

### PERF-0064 [LOW] The catch-up class drawer reads insights with the widest teacher token
- Units: shared:src/lib/nexus-swr.ts
- Check: AUTH-3 | Evidence type: inferred
- Location: components/catchup/ClassesRecapsTab.tsx:1109
- Root cause: `getTeacherToken` (`nexusTeacher` scopes) feeds the panel's reads as well as Sync from Teams, which does need the delegated token (`attendance-report` route:295).
- Evidence: `getAccessToken` redirects when silent refresh fails, and returns null within 60s of a previous redirect.
- User impact: a read-only view can bounce the teacher to Microsoft.
- Technical impact: a request with no token becomes a 401.
- Recommended fix: an optional `getReadToken` prop for the panel's reads.
- Risk: LOW. It touches files another session is editing, so it is deferred until that work lands.
- Expected improvement: reads never need teacher-only scopes.
- Status: open
