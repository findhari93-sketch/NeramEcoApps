# Tools App performance audit, 2026-10-01

First audit of `apps/app` (aiArchitek, app.neramclasses.com). The scope was the Tools tab: every `/tools/*` route, the public `/tools` SEO pages, the seven `/api/tools/*` routes, and the shell, layouts, packages and config they run in. The same session redesigned the app's interface, so most fixes below landed together with the redesign. Everything is uncommitted and nothing is deployed.

## Scope and coverage
- Planned: 44 units (focus: `tools`). Audited: 44. Skipped as fresh: 0. Deferred: 0.
- Re-audits: none (first audit of this app).
- Coverage after this session: 44 of 162 units have an audit record; 118 have never been audited (mostly `api/*` routes outside the Tools tab). 33 audited units already read `stale:code` because the fixes changed them after planning. That is expected, and the next session should review those diffs.
- Evidence sources used:
  - Read-only curl against production: response headers, `x-vercel-id`, server HTML, and chunk contents.
  - Read-only `pg_stat_statements`, row counts, the advisors, and `EXPLAIN` on prod.
  - `next dev` on port 3011 with Playwright: Pixel 5 and Desktop Chrome, at 375, 768, 1024 and 1440 px.
  - `tsc --noEmit` on `apps/app` (0 errors).
  - Vitest: 89 tests across `apps/app`, all passing.

## Performance audit report
1. **Top problems, worst first**
   - PERF-0001: functions ran in iad1 while the DB is in Singapore. Fixed.
   - PERF-0057: the same region finding, raised on the routes. Fixed.
   - PERF-0002: every hard load waits on `register-user`. Partly fixed.
   - PERF-0055: candidate personal data. Redacted; the app side is fixed and the DB side is open.
   - PERF-0056: the JoSAA predictor re-submits forever. Fixed.
   - PERF-0058: 10 to 22 sequential DB round trips per prediction. Open.
   - PERF-0059: counselling tools open on an empty system. Fixed.
   - PERF-0060: SEO pages are unreachable. Open; needs a decision.
   - PERF-0061: duplicate predictions. Fixed.
   - PERF-0030: fixed bars hidden under the tab bar. Fixed.
   - PERF-0003: Emotion SSR cache. Open, in a shared package.
2. **Production errors reported by the user:** none were reported.
3. **Failing or slow endpoints named by the user:** none were named. Measured instead: single-query GETs took 0.36 to 0.64 s warm and 1.3 to 1.85 s cold. The same response from cache took 0.13 to 0.18 s. All of this was cross-region (bom1 edge, iad1 function, Singapore DB).
4. **Why refresh fixes it:** does not apply. No "works after refresh" symptom was reported. Content under `(protected)` renders only on the client, so hydration mismatches inside tool pages cannot happen there.
5. **Slowest APIs**
   - `POST /api/tools/college-predictor/counseling`: not measured (needs a token). Inferred from 10 to 22 sequential round trips across regions (PERF-0058).
   - `POST /api/auth/register-user`: not measured end to end on prod. It runs 7 to 9 sequential queries and blocks the shell (PERF-0002). Locally against staging it took 2.4 s.
   - `GET /api/tools/counseling-insights`: 0.47 to 1.4 s, a cache MISS every time (PERF-0062, fixed).
6. **Duplicate requests on a hard load of a tool page**

   | Endpoint | Calls before | Expected | Cause |
   |---|---|---|---|
   | POST `/api/auth/register-user` | 1, blocking | 1, non-blocking | Layout gate (PERF-0002). Repeat loads in a tab now paint from cache. |
   | POST `/api/devices/heartbeat` | every 60 s, hidden tabs included | visible tabs only | PERF-0009, fixed |
   | Page search or prediction | 2 on the first tap | 1 | AuthGate re-fired the action (PERF-0032, PERF-0061, fixed) |
   | JoSAA POST after a failure | unbounded | 1 | Effect loop (PERF-0056, fixed) |
   | GET `/api/enrollment/pending` | 1 per hard load | 0 | PERF-0021, open |
7. **Largest components and bundles**
   - First-load JS for tool routes is about 450 kB gz, measured from prod chunks. MSAL ships through the `@neram/auth` barrel (PERF-0012). `ChatWidget` and other `@neram/ui` extras ship because the package has no `sideEffects` flag (PERF-0013).
   - The cutoff calculator page is 1,379 lines (PERF-0050).
   - The college predictor lost about 150 dead lines (PERF-0075, page part).
8. **Database and query bottlenecks**
   - No index is needed: the tables hold at most 11k rows and statement means are 0.2 to 11 ms.
   - Latency comes from round trips and region (PERF-0058, PERF-0001).
   - Advisor notes (recommend only):
     - Unindexed foreign keys on `josaa_or_cr`.
     - Several never-used indexes, worth reviewing before dropping any.
     - A `tool_usage_logs` RLS policy that re-evaluates per row.
     - Duplicate permissive SELECT policies on `counseling_college_directory`.
9. **Most expensive renders**
   - Keystroke state at page level in the cutoff calculator (PERF-0050).
   - `SidebarContext` value not memoised (PERF-0026).
   - Nothing was measured with the profiler.
10. **Recommended fixes still open (finding, fix, owner app)**
    - PERF-0055: revoke anon SELECT, or expose a view without the personal columns, and drop those columns from the selects in `packages/database`. Owner: database.
    - PERF-0058 and PERF-0063: one `predict_counseling` RPC, and `unstable_cache` keyed by inputs. Owners: app and database.
    - PERF-0002: render the shell as soon as the Firebase user exists and gate only the phone modal and onboarding on `register-user`. Move the analytics writes off that response path. Owner: app.
    - PERF-0003 and PERF-0006: per-render Emotion cache with `useServerInsertedHTML`, and read the theme mode after mount. Owner: `@neram/ui`, all apps.
    - PERF-0012 and PERF-0013: a Firebase-only subpath for `@neram/auth`, and `sideEffects: false` on both packages. Owners: packages, all apps.
    - PERF-0060: remove the three legacy `/tools/*` redirects so the SEO pages render again, or drop those pages from the sitemap and robots. Owner: app, decided by SEO.
    - PERF-0008: pass a `getToken()` function instead of a captured token. Owner: app.
    - PERF-0064: `waitUntil` for `logToolUsage`. Owner: app.
    - PERF-0065: check DB errors instead of falling back to empty data. Owner: database.
    - PERF-0031: return a locked body from the server. Redacted; owner: app.
11. **Estimated impact (not measured)**
    - Region pin: each DB round trip drops from a trans-Pacific hop to an in-region one. That matters most on the 10 to 22 round-trip prediction.
    - Shell cache: repeat hard loads in a tab skip one blocking request.
    - AuthGate removal: halves search and prediction POSTs on the first tap.
12. **Risk of each change**
    - Region pin: low. Verify `::sin1::` in `x-vercel-id` after deploy.
    - Shell cache: low. It is sessionStorage, keyed by uid, cleared on sign-out, revalidated on every load, and a first visit behaves as before.
    - Theme change: medium. It touches every screen in the app. It was checked in both modes at four widths for the Tools tab only.
    - Page rewrites: medium. API contracts are unchanged, but the behaviour was not exercised against real data beyond screenshots.
13. **Implementation order:** PERF-0055 (DB, needs approval), then PERF-0058 and PERF-0063, then PERF-0002, then PERF-0003, PERF-0006, PERF-0012 and PERF-0013 together (they touch shared packages, so they rebuild all four apps), then PERF-0060.
14. **Needs approval before doing:**
    - PERF-0055 (RLS and grants).
    - PERF-0058 (new SQL function).
    - PERF-0003, PERF-0006, PERF-0012 and PERF-0013 (shared packages, cross-app).
    - PERF-0060 (SEO routing).
    - PERF-0004 (registering the service worker changes offline behaviour).
15. **Fixed this session (all uncommitted)**
    - **Measured or verified:** PERF-0001, PERF-0057 (`vercel.json` regions `sin1`); PERF-0007 (fonts applied, Inter dropped); PERF-0011 (`global-error.tsx`, `not-found.tsx`, one reload on `ChunkLoadError`); PERF-0019 and PERF-0020 (shell rewrite, branded splash); PERF-0030 (fixed bars use `--app-bottom-inset`).

    - **Page fixes:** PERF-0032, 0033, 0035 to 0049, 0052, 0053, 0056, 0059, 0061, 0066 to 0071, 0073, 0077, 0078.

## Findings
All 79 findings, with every field, are in `docs/audits/perf/app/findings.jsonl` (`node .claude/skills/perf-audit/ledger.mjs finding list --app app`). Status after this session: 42 fixed and 37 open (5 HIGH, 14 MEDIUM, 18 LOW). The open HIGH findings:

### PERF-0002 [HIGH] Whole shell and page content blocked behind POST /api/auth/register-user on every hard load
- Units: layout:(protected)
- Check: LOAD-2 | Evidence type: measured (prod HTML is "Loading..." only) and inferred (the 7 to 9 query chain)
- Location: apps/app/src/app/(protected)/layout.tsx
- Recommended fix: render the shell once the Firebase user exists, and gate only the phone modal, onboarding, install banner and report button on registration.
- Status: partly fixed. Repeat loads in a tab paint from a sessionStorage profile and revalidate in the background (`registered-user-cache.ts`). First loads still wait.

### PERF-0003 [HIGH] NeramThemeProvider uses one module-level Emotion cache on the server
- Units: pkg:@neram/ui
- Check: HYD-1 | Evidence type: measured (prerendered HTML missing MUI CSS classes)
- Location: packages/ui/src/theme/provider.tsx
- Recommended fix: a per-render cache plus `useServerInsertedHTML`, the same pattern as `ThemeRegistry.tsx`.
- Status: open (shared package, needs approval).

### PERF-0055 [HIGH] Personal data exposure in counseling data tables and responses
- Redacted. The app-side part is fixed; the database part is open and needs approval.

### PERF-0058 [HIGH] Counseling college prediction makes 10 to 22 sequential DB round trips
- Units: route:api/tools/college-predictor/counseling, pkg:@neram/database
- Check: API-1 | Evidence type: inferred
- Location: packages/database/src/queries/counseling.ts:497-706, 1436-1496
- Recommended fix: parallelise the independent steps now, then one SQL function.
- Status: open.

### PERF-0060 [HIGH] Three public SEO tool pages are unreachable
- Units: page:tools/college-predictor, page:tools/cutoff-calculator, page:tools/exam-centers
- Check: NAV-1 | Evidence type: measured (308, then a loader-only page)
- Location: apps/app/next.config.js (redirects), src/app/sitemap.ts, src/app/robots.ts
- Recommended fix: remove the three redirects, or remove the URLs from the sitemap and robots.
- Status: open (SEO decision).
